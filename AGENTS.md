# Гофермарт

- Источник требований к сервису — `SPECIFICATION.md` в корне репозитория.
  Перед реализацией прочитай раздел ТЗ, относящийся к задаче.
- Работай в рамках текущего этапа. Изменяй только файлы, необходимые для задачи.
- Подключение новой зависимости обоснуй в итоговом отчёте.

## Стиль кода

- Форматируй изменённые Go-файлы через `gofmt`.
- При передаче ошибок добавляй контекст операции. Используй `%w`, если
  вызывающий код проверяет исходную ошибку через `errors.Is` или `errors.As`.
- Документируй пакеты и экспортируемые функции, типы и переменные.
- Комментарии пиши кратко и понятно. На английском.
- Пиши код просто, понятно и лаконично. Повышай читаемость кода (пустые строки, декомпозиция функций).
- Избегай дублирования кода.
- Имена пакетов и функций называй в соответствии с принятым стилем в Go.

## Ограничения

- Соблюдай HTTP-контракт из `SPECIFICATION.md`.
- Хранилище — PostgreSQL. Изменения схемы оформляй миграциями.
- Храни номера заказов строками. ТЗ допускает номера произвольной длины.
- Применяй начисление по заказу однократно. При списании проверяй
  остаток, обновляй баланс и записывай историю в одной транзакции.
- Не делай без моего разрешения коммиты.
- Задавай мне вопросы, если для работы не хватает информации.
- Согласовывай со мной выбор зависимостей, структуру пакетов, схему БД и способ
  аутентификации.

## Проверки

- Для нового поведения сначала напиши тест (используй TDD).
- После изменений Go-кода запускай `go test ./...` и `go vet ./...`.
- Поддерживай покрытие юнит-тестами не ниже 60%.
- Для проверки покрытия запусти `go test -coverprofile=coverage.out ./...`, затем
  `go tool cover -func=coverage.out`. Общий результат смотри в строке `total`.
- В конце задачи укажи, какие проверки прошли и какие не удалось запустить.
